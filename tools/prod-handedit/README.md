# Прод-правки, которых нет в git

Каталог фиксирует изменения, сделанные **прямо на сервере**: их нет ни в рабочем
дереве, ни в истории git. По правилам проекта (`CLAUDE.md`, `.cursor/rules/`)
править прод руками нельзя — но такие правки существуют, и обычный деплой
«с рабочего дерева» их молча стирает. Здесь они лежат как патчи, чтобы
восстановить или осознанно перенести.

Родственный механизм: `tests/reports/ASSET-PROD-DIFF-ACK.json` — там
подтверждаются «чужие» строки ассетов по разбору `audit_silent_reverts.js`.

## academy-cron-priority0.patch

**Файл:** `src/services/academy-cron.js`
**Что:** блок «ПРИОРИТЕТ 0: любая published-лекция БЕЗ картинок» в
`catchUpMissingLesson()` — 40 строк.
**Зачем:** догон смотрел только вперёд (`maxWeek + 1`) и не замечал лекции,
опубликованные до заливки генератора картинок (например, #160). Теперь сначала
дорисовываются «лысые» лекции, потом берутся новые слоты.

**Провенанс (проверено 20.10.2026):**
- в рабочем дереве блока нет;
- `git log --all -S "ПРИОРИТЕТ 0"` — пусто;
- прямая проверка блобов во всех 15 ревизиях файла в истории — блок не найден.

Вывод: правка внесена на сервере мимо git.

**Как применить к локальному файлу:**

```bash
git apply tools/prod-handedit/academy-cron-priority0.patch
```

Перед деплоем бэкенда проверить, что блок либо применён, либо сознательно
отброшен — иначе сервер вернётся к версии без дорисовки иллюстраций.

Источник-снимок прод-файла: `tests/reports/PROD-academy-cron.js`
(каталог в `.gitignore`, поэтому патч и есть носитель правки).
