# Тинг — поддержка и эксплуатация (runbook)

Дата: 2026-11-05
Для кого: поддержка, дежурный SRE, администратор CRM.

## Первые 60 секунд: что проверить

```bash
curl -s https://asgard-crm.ru/api/thing/health | jq
```

Ожидаемо: `ok: true`, `livekit: true`, `db: true`, `disk.free_mb > 5000`.

| Симптом | Первая проверка | Действие |
|---------|-----------------|----------|
| «Тинг не создаётся» | `health.livekit` = false | поднять LiveKit: `docker compose -f /opt/asgard-livekit/docker-compose.yml ps` |
| «Гость не входит» | `ROOM_LOCKED` / `BANNED` в ответе | хост закрыл вход или кикнул — это ожидаемо |
| «Не подключается из офиса» | TURN: см. `ops/livekit/README.md` | открыть UDP 30000–39900 в двух фаерволах |
| «Комнаты висят живыми» | `health.rooms.live` растёт без встреч | webhook не доходит — проверить `POST /api/thing/sweep` (ADMIN) |
| «Записи нет» | `thing_recordings.status` | `failed` → смотреть `error_text`; `recording` без участников — sweeper закроет |
| «Запись не скачивается» | `file_path` начинается с `s3://` | проверить S3-креды, иначе 503 «Хранилище недоступно» |

## Частые вопросы гостей

**Не слышно меня.** Проверьте в браузере значок микрофона на адресной строке; в лобби полоска уровня должна двигаться при разговоре. Если полоска стоит — выбран не тот микрофон в «Ещё → Микрофон».

**Не видно меня.** Камера занята другим приложением (Zoom/Teams/скайп). Закройте его и нажмите «Камера» снова.

**Не подключаюсь с рабочего ноутбука.** Корпоративный файрвол часто режет UDP. Тинг сам перейдёт на TURN, но если сеть разрешает только 443 — нужен TURN/TLS. Сообщите администратору.

**Чёрный экран при входе.** Обновите страницу; если не помогает — браузер старше 2 лет. Нужен Chrome/Edge/Safari актуальной версии.

**Меня удалили и не пускает.** Кик действует 24 часа в этой комнате. Организатор может снять ограничение — попросите его.

**Идёт запись — я против.** Индикатор «Идёт запись» показывается только когда запись реально включена. Вы можете покинуть встречу; запрос на удаление записи направляется организатору.

## Что сообщать в поддержку (шаблон тикета)

```
Комната: <slug или ссылка>
Роль: организатор / гость / телефон
Устройство: ОС + браузер (или Android TV модель)
Сеть: офис / дом / LTE
Время (МСК):
Что делал:
Что ожидал:
Что произошло:
Скриншот/лог консоли:
```

## Ограничения, о которых говорим честно

| Ограничение | Причина |
|-------------|---------|
| iOS: нет демонстрации экрана | `getDisplayMedia` отсутствует в Safari; нужен native-клиент |
| iOS: звонок засыпает в фоне | ограничение WebKit, не баг Тинга |
| 40 участников — не все с камерой | один сервер, комната живёт на одной ноде; `max_video` честно ограничивает |
| Эхо на Android TV | у приставок обычно нет аппаратного AEC; помогает гарнитура зала |
| Вебинар: зрители не публикуют | это режим, а не сбой |

## Эскалация

| Уровень | Кто | Когда |
|---------|-----|-------|
| L1 | поддержка | вход, устройства, «не слышно» |
| L2 | дежурный SRE | health, TURN, запись, webhook |
| L3 | разработка | воспроизводимый баг в коде, потеря данных |

SLA первой реакции: L1 — 1 час в рабочее время, L2 — 30 минут, потеря записи — немедленно.

## Retention записей

Политика: записи старше 90 дней удаляются. Реализация — lifecycle policy бакета S3
(`S3_BUCKET`), не cron приложения: так удаление не зависит от живости сервиса.
Файлы на локальном диске (если S3 не настроен) — ручной cron, см. `ops/livekit/README.md`.
