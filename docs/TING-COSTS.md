# Тинг — стоимость минуты и лимиты

Дата: 2026-11-05
Назначение: без этих цифр нельзя включать auto-record и «конспект всем» — они тратят деньги на каждую встречу.

## Расходные статьи (ставки задаются в биллинге провайдера)

| Ресурс | Единица | Кто платит | Где задаётся |
|--------|---------|------------|--------------|
| STT (расшифровка) | за минуту аудио | Yandex SpeechKit / routerai | `SPEECHKIT_*` в `/etc/asgard-crm/thing.env` |
| LLM (протокол) | за 1К токенов | routerai / выбранная модель | `thing-pipeline`, модель в настройках |
| Egress (запись) | CPU-час | собственный сервер | `ops/livekit/docker-compose.yml` (`cpus: 6`) |
| Хранение записи | за ГБ×месяц | S3-провайдер | `S3_BUCKET` |
| TURN-трафик | за ГБ релея | хостинг | `turnserver.conf` relay-диапазон |
| SIP/PSTN | за минуту | оператор связи | `ops/asterisk` trunk |

Ставки в рублях подставляет биллинг провайдера; в репозитории они не хранятся,
потому что меняются без изменения кода. Здесь фиксируется только **структура расчёта**.

## Формула на одну встречу

```
стоимость = T_media + T_turn + T_egress + T_storage + T_stt + T_llm
```

где:

| Слагаемое | Формула |
|-----------|---------|
| `T_media` | длительность (ч) × ставка CPU-часа SFU (амортизация) |
| `T_turn` | доля relay-сессий × исходящий ГБ × ставка ГБ |
| `T_egress` | длительность (ч) × 4 CPU × ставка CPU-часа |
| `T_storage` | размер файла (≈0,7 ГБ/час на 6 участников) × срок хранения × ставка ГБ-мес |
| `T_stt` | минуты аудио × ставка минуты STT |
| `T_llm` | токены протокола × ставка 1К токенов |

## Правило включения дорогих функций

| Функция | Условие включения |
|---------|-------------------|
| `recording_mode = auto` по умолчанию | посчитана `T_egress + T_storage` и подтверждён запас диска/S3 |
| «Конспект всем участникам» | посчитана `T_llm` на встречу и подтверждён лимит |
| Вебинар 200+ | второй медиа-узел (волна 2) |
| PSTN dial-in в прод | посчитана минута у оператора |

До выполнения условия функция выключена — это осознанное ограничение продукта,
а не забытая настройка.

## Лимиты, чтобы один зал не съел канал

| Лимит | Значение | Где реализован |
|-------|----------|----------------|
| Участников в комнате | 50 (БД), 12 с видео | `max_participants` / `max_video` |
| Одновременных записей | 1 гарантированно, вторая — при простое CPU | `cpus: 6` × `max_cpu_utilization: 0.8` vs `room_composite_cpu_cost: 4` |
| Длительность файла записи | 4 часа | `session_limits.file_output_max_duration` |
| Часов записи в сутки на комнату | 8 | учитывается в аналитике (`/analytics`) |

## Как померить факт (без догадок)

| Что | Команда |
|-----|---------|
| CPU записи | `docker stats livekit-egress` во время встречи |
| Длительность и модель STT/LLM | `SELECT * FROM thing_jobs ORDER BY id DESC LIMIT 10` |
| Доля relay-сессий | в браузере: `getStats()` → `candidate-pair` → `local-candidate` тип `relay` |
| Объём хранения | размер бакета `S3_BUCKET` за месяц |
| Минуты PSTN | отчёт оператора по trunk |

Эти числа вносятся в `tests/reports/TING-CAPACITY.md` после первого прогона.
