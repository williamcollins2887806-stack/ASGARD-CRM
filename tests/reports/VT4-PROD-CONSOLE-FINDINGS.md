## Сигнал 1. `Uncaught TypeError: Cannot read properties of undefined (reading 'startTime')` из `VM240:2`

### Что такое `VM240`

`VM###` — имя скрипта, созданного динамически (`new Function` / `eval`), а не загруженного файла.

### Что проверено (и что это дало)

| Проверка | Результат |
| --- | --- |
| Все `new Function(`/`eval(` в ванильном фронте | **ровно одно место**: `public/assets/js/asgard_smeta.js:147` |
| `new Function`/`eval` в `sw.js`, `index.html` | нет |
| Литерал `startTime` в исходниках vanilla / v2 / mobile | только `performance.now()`-таймеры и `startTimer()`; **ни одного** чтения свойства `.startTime` |
| `startTime` в данных клона | `tender_rp_reviews.report_json` — нет; `settings.value_json` — нет |
| `git log -S "startTime"` по зеркалу сметы | **0** — в зеркале сметы `startTime` **никогда не было** |
| `javascript:` URL (источник VM-скриптов) в `public/` | нет (совпадения — в комментарии `registry_tab.js` про XSS-фильтр) |

### Единственная точка динамического исполнения

`public/assets/js/asgard_smeta.js:147`

```js
const safe = String(expr).replace(/[^a-z0-9_.*+\-/() ]/gi, '');
// eslint-disable-next-line no-new-func
const fn = new Function('m', `with(m){ return (${safe}); }`);
const v = fn(map);
```

Тело, переданное в `new Function`, движок оборачивает в функцию; строка 2 обёртки —
это `with(m){ return (...); }`. То есть стек `VM240:2` согласуется с вычислением
**формулы сметы** (`evalQtyExpr`, строки 114-152).

### Честный вывод

Выражение пришло из **данных** (поле формулы в просчёте), а не из кода: в дереве такого
литерала нет и никогда не было. Чтобы закрыть, нужен сам просчёт. **Статически источник
не устанавливается** — и я не буду делать вид, что установил.

### Что нужно, чтобы закрыть (живой прогон)

1. Воспроизвести в chromium на `:3100`, открыть консоль, поймать полный стек с аргументами.
2. ИЛИ найти в проде просчёт с формулой, содержащей `startTime`
   (на проде есть данные, которых нет в клоне; проба read-only):
   `SELECT id FROM tender_rp_reviews WHERE report_json::text ILIKE '%startTime%'`.
3. Решение — одно из: (а) исправить сохранённую формулу; (б) заменить `with(m)`
   на явный доступ к `map` с понятной ошибкой вместо TypeError; (в) оба.

### Отдельно: риск в самой конструкции

`new Function` + `with(m)` исполняет **сохранённое в БД** выражение. Фильтр пропускает
идентификаторы, точки, скобки и арифметику, но `with(m)` при отсутствии имени в `map`
разрешает его **через глобальную область**. Значит, формула из БД потенциально может
дотянуться до глобального объекта. Оценку этого риска надо делать при закрытии —
не только «поправить TypeError».

**Статус: OPEN (не подтверждён), D-242.** Требует живой репродукции.

## Сигнал 2. `POST /api/warehouse-map/floors/1/sync-locations 403 (Forbidden)`

### Это D-158 — уже FIXED, VERIFIED и выкачено на прод

Запись `D-158` (ledger, стр. 3416): «`403 POST /api/warehouse-map/floors/1/sync-locations`
на каждой отрисовке карты (VERIFIED, вариант A)».

- Причина (до): фронт вызывал синк **автоматически при монтировании** (`warehouse-map.js:2597`
  внутри `refresh()`, из `renderMapTab:1536` и `mount:2871`). Для ролей вне `WMS_WRITE`
  это гарантированный 403 на каждой отрисовке.
- Правка (вариант A, выбран заказчиком 15.09): авто-POST убран; синхронизация осталась
  **явным действием** — кнопка «Синхр. QR» (`[data-a="sync"]`).
- VERIFIED: клон `:3100` — 6/6 PASS под ADMIN и 6/6 под PM; **прод** — 6/6 PASS,
  `md5` `warehouse-map.js` локально и на проде **совпадают**, шелл `20.28.32`.
  Выкачено 16.09.

### Что подтверждает текущий код

Повторная проверка дерева (21.09) это подтверждает: все обращения к `sync-locations`
в `warehouse-map.js` — это `onclick` **явных кнопок** (стр. 2367-2374 для объектов,
стр. 2768-2778 для этажей). Авто-вызова в `refresh()` нет.

### Подтверждение со стороны прода

`python tools/restore_asset_sync.py plan` (read-only, проверено сейчас):
`differ_prod_newer = 0`; `public/assets/js/warehouse-map.js` **отсутствует** в списке
расхождений. То есть прод-версия и рабочее дерево совпадают → авто-синка на проде нет.

**Статус: закрыто D-158.** Дополнительных правок не требуется. Повторный анализ
менять нечего — решение заказчика (вариант A) уже реализовано и проверено.

## Сигнал 3. `Failed to load resource: 503` на `/api/procurement/export/excel`

### Это D-159 — уже CLOSED

Запись `D-159` (ledger, стр. 3439): «`503 /api/procurement/export/excel`

закрытием по невоспроизводимости.

### Отдельное замечание (не дефект плана, но стоит знать)

Запрос идёт с `LIMIT 1000` и **коррелированными подзапросами** по позициям на каждую строку:

```sql
(SELECT COUNT(*) FROM procurement_items pi WHERE pi.procurement_id=pr.id) as items_count,
(SELECT COALESCE(SUM(pi.total_price),0) FROM procurement_items pi WHERE pi.procurement_id=pr.id) as items_total
```

При 1000 заявках это до 2000 подзапросов на один экспорт. Это запас на будущее,
не текущий дефект.

**Статус: закрыто D-159.** Правок не требуется.

## Сигнал 4 (дополнительно). Deprecation `three.min.js`

Источник: `public/assets/js/warehouse-map.js:51-54` — список кандидатов на загрузку:

```

'/assets/vendor/three.min.js'
'https://unpkg.com/three@0.160.0/build/three.min.js'
```

Локальный путь `assets/vendor/three.min.js` в списке есть, но **в `index.html` тега нет** —
библиотека грузится динамически при открытии 3D-карты. Предупреждение об устаревании
идёт от сборки three (r160 сообщает о переезде на ESM/`three.module.js`).

Не является дефектом функциональности, в ledger не зафиксировано. Решение (выбрать при закрытии):
- зафиксировать версию и задокументировать предупреждение, либо
- перейти на `three.module.js` при следующей правке 3D-карты (вне этого плана).

**Статус: зафиксировано, правка в рамках плана не требуется.**
